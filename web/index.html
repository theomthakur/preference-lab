    How it works

    From a question to a result

    The original 0.5B experiment compared SFT, DPO and GRPO. A separate 1.5B SFT continuation was later evaluated on newly generated frozen cases.

    1. 1

      Generate and split

      Synthetic policy scenarios with a rule oracle for the reference answer. Splits are by case, so no case appears in two splits.

    2. 2

      Train variants

      Fine-tune a 0.5B base model (SFT). Then try DPO on preference pairs and GRPO with a verifier reward, both starting from SFT.

    3. 3

      Score and inspect

      One checker grades the action and the exact evidence for every model. Saved predictions feed the paired comparisons.

    Separate track

    Tool environment. The base and SFT models were also run on 20 validation cases that needed tool calls. Both scored 0 of 20. Trained tool use was not achieved.

    Tech stack

    Model
    Qwen2.5-0.5B-Instruct
    Training
    Python, PyTorch, Transformers, TRL, PEFT (LoRA)
    Evaluation
    Python, JSONL, a rule-based verifier
    Hardware
    Apple M4, 16 GB, PyTorch MPS
    Dashboard
    Static HTML, CSS and JavaScript over one JSON file

    Why a rule oracle?

    It gives a repeatable reference answer. The task still reflects the assumptions written into its rules.

    Why paired evaluation?

    Every model answers the same cases, so differences can be compared case by case.
